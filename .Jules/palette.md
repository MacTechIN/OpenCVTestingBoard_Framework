## 2024-05-18 - File Upload Accessibility and Re-upload UX
**Learning:** In the custom ImageUploader component, clearing an uploaded image visually and logically (via `onClear`) doesn't automatically clear the underlying hidden `<input type="file">`. If a user removes an image and tries to upload the exact same file again immediately, the native `change` event won't fire because the browser thinks the value hasn't changed, causing a confusing UX where nothing happens. Also, absolute-positioned icon-only overlay buttons (like the remove image button over the uploaded image) must have an explicit `aria-label`, `aria-hidden="true"` on the internal icon, and specific focus styles so screen reader and keyboard users can successfully locate and activate them.
**Action:** When building custom file upload UI wrapping native hidden file inputs, always reset the input's value (e.g., `e.target.value = ''`) inside the `onChange` handler after processing the file. For icon-only overlay buttons, verify `aria-label` and `focus-visible:ring-2` classes are present during implementation.
